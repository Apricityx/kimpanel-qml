# 原生 Wayland 扩画布实验

[English](README.md) · **研究已暂停，不安装、不默认启用。**

原型在独立嵌套 niri 26.04 中使用真实 `zwp_input_popup_surface_v2`，同时模拟
text-input-v3 客户端与 input-method-v2 输入法。透明画布上绘制 120 × 48 的实心
标记，发送受控光标矩形，用截图像素测量真实屏幕位置。

它不加载 fcitx addon，不占用主桌面的输入法 seat，不重启桌面 compositor；但会
启动单独的 niri 窗口，可能短暂改变桌面焦点。源码保留用于后续研究，本次项目整理
不继续动画开发，也不运行此交互实验。

在仓库根目录手动复现：

```sh
make prepare
python3 experiments/canvas-probe/build.py
popup-venv/bin/python experiments/canvas-probe/check.py
```

依赖 niri、gcc、wayland-scanner、XML 协议和 PySide6。默认使用 `build/fcitx5/`
和系统开发包；可选 `--sysroot` 指定解包依赖。`build.py` 与 `check.py` 的
`--work-dir` 必须一致。产物、日志和截图在 `build/canvas-probe/`，退出时终止自己
创建的嵌套实例。

## 限制

扩画布和内部动画可行，但不能单独保证屏幕移动连续。应用改变光标后，niri 在
输入法提交补偿帧之前移动旧 popup。测试人为延迟以截取两种状态，证明有未同步
区间，**不证明每次真实按键都会显示坏帧**。快速 renderer 可能赶上下一个显示帧，
但现有协议没有原子同步保证。

边缘定位取决于整个 surface tree 的 bbox，扩画布本身会改变上下翻转或横向约束。
矩形事件不反馈最终 popup 原点/决策，当前 niri IPC 也没有精确平铺窗口屏幕原点。
完整实现需要重定位与像素同步、最终原点，或不随光标改变的稳定 surface 原点。
本实验不证明修改 compositor 是唯一方案，只证明当前简单扩画布方案尚不能用于
任意移动的默认前端。
